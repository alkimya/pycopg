<objective>
Add the three unary (single-column) geometry-processing operations to both spatial accessors:
`simplify` (ST_SimplifyPreserveTopology default / ST_Simplify, result col `simplified`),
`convex_hull` (ST_ConvexHull, result col `convex_hull`), and `make_valid` (ST_MakeValid, result col
`made_valid`). `simplify` has a required kw-only `tolerance` (D-05) and a two-branch SQL shape;
`make_valid` enforces a `{None, "linework", "structure"}` method whitelist (D-02) and assembles a
params string bound through `%s` (D-02), with `keep_collapsed` (structure-only, D-03). Contradictory
arg combos raise `ValueError` (D-03/D-05 recommended disposition). Each method is mirrored 1:1 on
`AsyncSpatialAccessor` in the same change (D-11) and carries `filter=` only (D-10).

Purpose: SPAT2-02/03/04 — deliver simplification, convex hull, and geometry repair without raw SQL,
exposing the full PostGIS knob set (the API freezes at 1.0).
Output: 3 public builders + 6 accessor methods (3 sync + 3 async) + SQL-shape, ValueError-guard,
injection, routing, and live-integration tests (bowtie, tiny-polygon, make_valid structure).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller -> build_*_sql | `table`/`schema`/`geom`/`columns` untrusted identifiers; `tolerance` untrusted numeric; `method`/`keep_collapsed`/`preserve_*` untrusted control values |
| caller -> accessor method | `filter`/`order_by` raw SQL fragments (documented caller responsibility); `into` whitelisted by `_check_into` |
| accessor -> PostGIS | `make_valid(method="structure")` requires server PostGIS >= 3.2; older servers raise a native error (D-04 passthrough) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-42-04 | Tampering (T1 identifier injection) | build_simplify_sql / build_convex_hull_sql / build_make_valid_sql via `table`/`schema`/`geom` | mitigate | `validate_identifiers(table, schema, geom)` is LINE 1 of each builder; per-builder injection test (`test_<op>_invalid_table`) asserts `InvalidIdentifierError` before any SQL |
| T-42-05 | Tampering (T1 columns injection) | `columns=` rendered by `_cols_str` | mitigate | `if columns: validate_identifiers(*columns)` after line 1; columns-injection tests assert `InvalidIdentifierError` |
| T-42-06 | Tampering (T2 value injection via tolerance) | `build_simplify_sql` numeric `tolerance` | mitigate | `tolerance` bound through `%s` (psycopg3 float serialization), never f-string; the `int()`-shortcut is NOT used (RESEARCH anti-pattern) |
| T-42-07 | Tampering (T2 value injection via make_valid method/params string) | `build_make_valid_sql` `method` + assembled params string | mitigate | `method` constrained to the `{None,"linework","structure"}` whitelist (ValueError otherwise); the params string is assembled ONLY from programmer-controlled literals and bound through `%s` — never interpolated (Pitfall 4); `test_make_valid_invalid_method` is the tripwire |
| T-42-08 | Denial of Service / correctness (older-PostGIS structure) | `make_valid(method="structure")` on PostGIS < 3.2 | accept | D-04 documented passthrough — no server-version round-trip; PostGIS raises its native error; documented in docstring + stability.md (42-03) |
| T-42-SC | Tampering | npm/pip/cargo installs | accept | This plan installs NO packages (modifies existing source only — RESEARCH "Package Legitimacy Audit": none required) |
