<objective>
Add keyword-only `origin: datetime | None = None` and `offset: str | None = None` params to
`db.timescale.time_bucket` on both accessor classes, so users can align bucket boundaries to a
custom absolute anchor (`origin`) or a relative interval shift (`offset`) (TSDB-F02).

Purpose: TimescaleDB's `time_bucket` supports origin/offset alignment via separate SQL overloads;
this exposes both through pycopg's existing `time_bucket` surface without breaking the current
signature (keyword-only, both default None = current behavior unchanged).

Output:
- `_build_time_bucket_sql` (:214) extended with two new optional params + a client-side
  mutual-exclusion `ValueError` guard (D-07), keeping `validate_identifiers` line 1.
- `origin`/`offset` added to all 3 `@overload` stubs + the impl signature on BOTH sync (:1207-1257)
  and async (:2323-2362) `time_bucket` — 8 signature edits total (mypy-strict KIND-parity, v1.0.0
  Phase 46 pattern).
- `TestTimeBucketOriginOffsetMock` SQL-shape + mutual-exclusion tests (sync + async).

RESEARCH §3 confirmed these are SEPARATE PostgreSQL overloads (no both-set variant) — the
client-side ValueError converts a confusing "no matching function" DB error into a clear message.
`time_bucket_gapfill` is OUT of scope (requirement names `time_bucket` only).
</objective>
