<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local repo → GitHub (tag push) | annotated tag crosses into the remote; the Release is created from it |
| GitHub Release event → PyPI | `release: published` triggers OIDC trusted publishing into the PyPI project |
| PyPI → end user (clean-venv smoke) | the published wheel is what a downstream `pip install` fetches |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51-08 | Spoofing / Elevation of Privilege | publish.yml OIDC trusted publishing | mitigate | No PyPI token/secret is stored in the workflow; publish uses OIDC trusted publishing scoped to the `pypi` environment with `id-token: write` only. Publish is gated on a human-published GitHub Release (D-07) — the executor cannot publish autonomously. |
| T-51-09 | Tampering | tag ↔ release provenance | mitigate | The annotated tag is created on the exact HEAD whose 5 gates were green (51-02); the GitHub Release is created from that same tag (Task 2 step 2 forbids creating a new tag), so the built artifact provenance chains commit → tag → release → PyPI. |
| T-51-10 | Tampering / Information Disclosure | published wheel integrity vs source | mitigate | Clean-venv smoke installs from the real PyPI index and asserts `__version__ == "1.1.0"` plus importable Phase 48-50 symbols — detects a wrong/tampered/mismatched artifact before the release is trusted. |
| T-51-11 | Denial of Service | premature/duplicate tag or release | mitigate | Task 1 verifies no pre-existing `v1.1.0` tag before creating; publish.yml on a duplicate version would fail PyPI's immutable-version rule — surfaced by the human-gate step 5 workflow check. |
| T-51-SC | Tampering | npm/pip/cargo installs | accept | The only install is `pip install pycopg==1.1.0` — the project's OWN just-published artifact, verified by the smoke assertions — not a third-party dependency. No `[ASSUMED]`/`[SUS]`/`[SLOP]` packages; Package Legitimacy Gate not applicable. |

Residual accepts: T-51-SC (self-install of the published artifact under smoke verification).
</threat_model>
