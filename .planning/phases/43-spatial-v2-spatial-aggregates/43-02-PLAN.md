<objective>
Add the third PostGIS geometry aggregate, `extent` (`ST_Extent`, SPAT2-09), to both spatial accessors.
`extent` is the one method whose builder must see `into=` (D-04 exception): `ST_Extent` returns a
PostgreSQL `box2d`, which is text-serializable but is NOT a PostGIS geometry. So `into="rows"` casts to
`::text` (returns the `BOX(xmin ymin, xmax ymax)` string) while `into="gdf"` wraps
`ST_SetSRID(ST_Extent(...)::geometry, int(srid))` to produce a real polygon GeoPandas can load. A single
`build_extent_sql(..., into)` branches on `into` (DRY — one builder, one branch, NOT two builders). The
GROUP-BY machinery, identifier validation, and `_append_tail` GROUP-BY extension all come from 43-01;
this plan reuses them and adds only the `extent`-specific dual-branch SQL and the `srid` knob.

Purpose: Deliver SPAT2-09 at full sync/async parity, completing the 3-method aggregate surface. `extent`
introduces the `srid: int = 4326` keyword-only parameter (consulted only on the gdf cast via `int(srid)`,
the injection-safe convention from `build_point_geom`/`build_transform_sql`). T-43-01 still applies — the
new `group_by` columns are untrusted identifiers and `validate_identifiers` is line 1 of `build_extent_sql`.
Output: 1 dual-branch builder + 1 sync method + 1 async method + extent SQL-shape/branch/injection/routing
tests appended to `TestAggregateBuilders`.
</objective>
