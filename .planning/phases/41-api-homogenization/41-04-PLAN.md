param order, `into=` defaults, `schema=` defaults, return shapes, kw-only boundary), produce a
findings table, PAUSE for user review (D-05 — non-negotiable: the user reviews the inventory BEFORE
any fix lands), then apply the approved fixes. Per-finding disposition (D-06): NAME renames → one-cycle
deprecation alias (DeprecationWarning + MIGRATION, removed in 2.0); STRUCTURAL / positional / default /
kw-only changes → clean 1.0 breaks with MIGRATION entries.

The headline structural change is keyword-only enforcement (D-03/D-04): required identifier args stay
positional (`table`, `geom` where required, `within`'s 4 identifiers); ALL optional/defaulted params
become keyword-only by moving the `*` boundary. This ships as a CLEAN 0.x→1.0 break — NO positional
shim. Note `within()` has 4 required positional args before its `*` — flag its boundary explicitly.

Purpose: a frozen, uniform positional-vs-keyword-only contract for every public method so Phase 46
mypy-strict `@overload` work only covers the keyword-only surface (D-04 rationale).
Output: findings table (reviewed), kw-only `*` enforcement across accessors + flat core, any approved
audit-surfaced renames with aliases, filled TestKwOnlyEnforcement tests.

NOTE: This plan is `autonomous: false` — Task 2 is a `checkpoint:human-verify` review gate that MUST be
approved before Task 3 runs.
</objective>
