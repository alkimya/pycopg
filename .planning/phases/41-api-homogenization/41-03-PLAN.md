<objective>
FREEZE-01: Rename the spatial raw-SQL-fragment parameter from `where=` to `filter=` across the entire
spatial surface so that `where=` can mean dict-equality consistently everywhere else. The 11
module-level `build_*_sql` builders and the single `_append_tail` choke-point (spatial.py ~line 148)
get a CLEAN `filter=`-only rename (no shim — they are the frozen public builder layer, D-04 boundary).
The 11 `SpatialAccessor` + 11 `AsyncSpatialAccessor` methods (22 accessor sites) get a per-signature
`filter=None, where=None` shim: if `where` is supplied, emit a `DeprecationWarning` with
`stacklevel=2` pointing at the CALLER's file (D-09), forward to `filter`; if BOTH are supplied raise
`TypeError`. Internal callers use `filter=` only (D-10). Sync/async parity is enforced (D-11).

ALSO update the spatial module docstring (~line 21) which documents `where=` as a raw SQL fragment.
The kw-only `*`-boundary move (promoting `geom`/`schema` to keyword-only) is FREEZE-03 territory and is
handled in Plan 04 after the audit review — this plan keeps the EXISTING positional boundary and only
swaps the parameter name + adds the shim, to keep the change reviewable and the dependency clean.

Purpose: vacate the `where=` name for dict-equality (Pitfall 7); set the `filter=` precedent that
Spatial v2 (Phases 42-44) builders adopt from day one.
Output: `filter=` on 33 signature sites + `_append_tail`, the where= shim on 22 accessor methods.
</objective>
