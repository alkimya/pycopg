<objective>
F01 (ETL-INC-F01): add a declarative `Pipeline.initial_watermark` field so the FIRST incremental
run is a bounded/seeded load (`WHERE col > initial_watermark`) instead of a full initial load.
Seed-floor-only semantics (D-01): the value is consulted ONLY when no stored watermark exists;
after the first successful run records `max(col)`, it is never used again.

Purpose: turn the v0.7.0 "first run = full load" behavior into an optional bounded first load,
without any breaking change — default `initial_watermark=None` reproduces today's behavior
byte-identically.

Output: `Pipeline.initial_watermark` frozen field + `__post_init__` construction guard (requires
`incremental_column`, scalar allowlist) + seed-floor fallback wired at all four `run()` watermark-read
call sites (sync real, sync dry-run, async real, async dry-run), both accessors edited in the same
commit (C-04). New `tests/test_etl.py::TestInitialWatermark`.
