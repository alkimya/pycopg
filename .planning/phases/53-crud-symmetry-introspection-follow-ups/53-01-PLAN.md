Add the missing predicate-read siblings to the flat transactional core: select_where / find (list[dict]) and get / find_one (dict | None), on both Database and AsyncDatabase. This is a pure mechanical mirror of the shipped count / delete_where / exists templates plus reuse of the already-built _resolve_predicate + _build_select_sql + fetch_all/fetch_one infrastructure — no new SQL-building logic.

Purpose: complete the CRUD-read symmetry (CRUD-F04, CRUD-F05) so users can do the common "filter + order + top-N" and "fetch one matching row" cases in one call instead of hand-writing SQL.
Output: 8 new methods (4 x sync + 4 x async), unit + injection + live-DB integration tests.

| Boundary | Description |
|----------|-------------|
| caller -> select_where/get SQL | table/schema/columns identifiers + dict-where keys are untrusted identifiers; where values / where_params are untrusted values; where_sql / order_by are caller-owned raw SQL text (trusted by contract) |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-01 | Tampering | table / schema / columns identifiers on select_where / find / get / find_one | mitigate | validate_identifiers runs first inside _build_select_sql (base.py:281-283) before any SQL executes; dedicated parametrized identifier-injection tests in tests/test_sql_injection.py assert InvalidIdentifierError (Task 1/2) |
| T-53-02 | Tampering | dict-where values + where_params on the reads | mitigate | all user values bound as positional %s via _resolve_predicate -> fetch_all/fetch_one, never f-string interpolated; TestWhereSqlValueInjection asserts binding (Task 1/2) |
| T-53-03 | Tampering | order_by / where_sql raw-SQL escape hatches | accept | caller-owned raw SQL by design (same trust model as shipped where_sql on count/delete_where, base.py:340-345); documented in docstrings; a dedicated order_by test proves multi-column syntax passes through and is intentional, not a validation bypass (Task 1) |
