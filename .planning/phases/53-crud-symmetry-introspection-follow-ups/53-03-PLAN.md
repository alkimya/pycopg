## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller -> column_exists / table_size | table / schema / column names are untrusted identifiers; column_exists binds them as %s values against information_schema.columns (no identifier interpolation); table_size validates name/schema then binds the qualified name as a %s text arg |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-01 | Tampering | table / schema / column identifiers on column_exists and table_size | mitigate | column_exists binds 3 values as %s vs information_schema.columns (never interpolated, D-08); table_size runs validate_identifiers(name, schema) first (truncate_table guard) then binds the qualified name as %s; parametrized identifier-injection tests assert InvalidIdentifierError for table_size and that column_exists never interpolates (Task 1) |
| T-53-02 | Tampering | bound catalog-query values | mitigate | all values (schema, table, column, qualified 'schema.name') passed as positional %s params via self._db.execute(CONST, [...]), never f-string interpolated (Task 1) |
| T-53-01b | Information Disclosure | table_size leaking psycopg UndefinedTable on a missing table | mitigate | existence guard raises the library's TableNotFoundError with a clean 'schema.table' message before the size query runs, never leaking the raw driver error and never returning 0 (D-09); unit + integration tests assert the guard (Task 1/2) |
</threat_model>
