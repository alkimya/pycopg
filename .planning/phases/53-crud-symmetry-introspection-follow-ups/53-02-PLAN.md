<objective>
Add the single-row insert helper to the flat transactional core on both Database and AsyncDatabase — the singular twin of insert_many / upsert. It is a near-copy of upsert's build -> append RETURNING * -> bind -> fetchone tail (database.py:1007-1013), minus the conflict-column computation: insert's on_conflict is a raw passthrough string.

Purpose: complete the write symmetry (CRUD-F06) so users can insert one row and get RETURNING * back without forcing a 1-element list through insert_many.
Output: 2 new methods (sync + async), unit + injection tests, live-DB integration tests (incl. the DO NOTHING -> None path), and the v1.2.0 flat-core surface test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller -> insert SQL | table / schema identifiers + row keys (column identifiers) are untrusted; row values are untrusted values; on_conflict is a caller-owned raw SQL fragment (trusted by contract, mirrors insert_many) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-01 | Tampering | table / schema / row-key (column) identifiers on insert | mitigate | validate_identifiers runs inside _build_insert_sql (base.py:169) before any SQL executes; parametrized row-key/table/schema injection tests assert InvalidIdentifierError (Task 1) |
| T-53-02 | Tampering | inserted row values | mitigate | values bound as positional %s in row.keys() order via cursor.execute(sql, params), never interpolated (Task 1) |
| T-53-03 | Tampering | on_conflict raw-SQL passthrough | accept | caller-owned raw SQL by design (same trust model as insert_many/upsert on_conflict, D-06); documented in docstring; values inside a DO UPDATE clause remain the caller's responsibility to parameterize |
</threat_model>
