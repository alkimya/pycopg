<objective>
Add transaction-control surface to the flat core on BOTH `Database` and `AsyncDatabase`
(sync/async parity, kw-only per D-04):

1. `transaction(*, isolation_level=None, savepoint_name=None)` — set isolation on the fresh
   per-call connection; raise inside an active `session()` (D-03); open a named savepoint via
   psycopg's native `conn.transaction(savepoint_name=...)` (D-02).
2. `session(autocommit=False, *, isolation_level=None)` — set the level on the session
   connection right after connect (D-03); `autocommit` stays positional, `isolation_level` kw-only.
3. `savepoint(*, name=None)` — standalone context manager for a nested savepoint inside an active
   session, delegating to psycopg's native savepoint; `name=None` auto-generates (D-02).

Purpose: users control isolation and do partial rollbacks without raw SQL, honoring the
"honest about the constraint" choice (raise rather than silently ignore in-session isolation).

Output: extended `transaction()`/`session()` + new `savepoint()` on both classes, plus
`tests/test_transaction_isolation.py` (TXN-01 unit) and `tests/test_savepoints.py` (TXN-02
integration).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → `savepoint(name=)` / `transaction(savepoint_name=)` | a caller-supplied savepoint name reaches the database |
| caller → `transaction/session(isolation_level=)` | a caller-supplied enum member selects the isolation level |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-03 | Tampering (SQL injection via savepoint name) | `savepoint(name=)`, `transaction(savepoint_name=)` | mitigate | The name is passed ONLY to psycopg's native `conn.transaction(savepoint_name=...)`, which safely quotes the savepoint identifier internally — pycopg never string-interpolates the name into raw SQL, so no injection path exists. No new SQL builder is introduced, so no `validate_identifiers` site is required. |
| T-45-04 | Tampering (unexpected isolation downgrade) | `isolation_level` while in-session | mitigate | Setting `isolation_level` inside an active session would be silently ignored by psycopg (cannot change mid-transaction); D-03 instead RAISES a `RuntimeError`, preventing a caller from believing they set SERIALIZABLE when they did not — a fail-closed, honest-about-the-constraint design. |
| T-45-05 | Denial of service (leaked session connection) | `session()` `finally` cleanup | accept | The existing `session()` commit/close/cleanup `finally` block is left untouched; the new `isolation_level` set happens before the `try:` and cannot bypass cleanup. No new leak path introduced. |

No `high`-severity threats. The only caller-tainted value reaching SQL (savepoint name) is handled by psycopg's parameterized savepoint API.
</threat_model>
