<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → `execute/fetch_*/to_dataframe(params=)` | a caller-supplied mapping/sequence of bind values reaches the driver |
| `health()` failure → `error` string | a psycopg exception message is surfaced to the caller in the `error` key |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-06 | Tampering (SQL injection via named params) | widened `params` on execute/fetch_*/to_dataframe | mitigate | The widening is annotation-only (D-12). Values are bound by psycopg (`%(name)s`) / SQLAlchemy (`:name`) as parameters, never interpolated into SQL text. No `_rewrite_named_params`/translator is added (grep-asserted), so no new string-building injection surface exists. |
| T-45-07 | Information disclosure (connection details in health error) | `health()` `error` key | mitigate | The `error` value is `str(exc)` of psycopg's own exception — the same text the caller would see if they caught the error themselves. pycopg does not append the DSN, password, or `connect_params()` to the message. `health()` returns `server_version`/`latency_ms` only, never the connection string. Verified by `test_health_never_raises` asserting the error text is the driver message. |
| T-45-08 | Denial of service (health probe hangs a monitoring loop) | `health()` connect path | accept | `health()` uses the same connection acquisition as every other call; it adds no unbounded wait. Connect-timeout is governed by the existing `Config`/DSN settings, unchanged by this phase. A never-raises probe that returns `connected: False` on failure is strictly safer for monitoring loops than one that throws (D-05). |

No `high`-severity threats. The only new caller-tainted-to-SQL surface (named params) is parameter-bound, and the health error path surfaces only the driver's own message.
</threat_model>
