<objective>
Apply the coarse structured-logging instrumentation (D-09) — the second half of LOG-01 — by
wrapping the meaningful, already-non-trivial operations in `log_operation`, and NOTHING in the
per-call query hot path:

- `etl.py`: `ETLAccessor.run` + `AsyncETLAccessor.run` → `log_operation("etl.run", rows=<count>)`
- `backup.py`: `pg_dump`/`pg_restore` on `BackupAccessor` + `AsyncBackupAccessor` →
  `log_operation("backup.pg_dump"|"backup.pg_restore")`
- `migrations.py`: `Migrator.migrate` → `log_operation("migrations.migrate", rows=len(applied))`
- `database.py` + `async_database.py`: `from_dataframe`/`from_geodataframe` (the COPY paths) →
  `log_operation("database.from_dataframe"|"database.from_geodataframe", rows=len(df|gdf))`

Purpose: applications that opt into pycopg logging see operation name + duration (+ row count
where available) for the heavyweight operations, without paying per-query timing cost or
freezing an instrumentation site on every `execute()` under SemVer.

Output: `with log_operation(...)` wrappers at the listed sites (no behavior/return change) and a
`test_instrumentation_sites` smoke test in `tests/test_logging_module.py`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| wrapped operation internals → log record | operation name + duration + row count are emitted when an app opts into logging |
| existing op behavior → caller | the wrapper must not alter return values, exceptions, or existing log levels |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-09 | Information disclosure (sensitive data in instrumentation logs) | `log_operation` call sites | mitigate | Each site passes only a constant operation-name string and an integer `rows` count — never the DataFrame contents, SQL, table data, backup file paths' secrets, or DSNs. (pg_dump/pg_restore pass NO rows; their op name is a constant.) The record shape is fixed by `log_operation` (Plan 01, T-45-01). |
| T-45-10 | Tampering (instrumentation alters operation behavior) | wrapped bodies in etl/backup/migrations/copy | mitigate | Wrapping is a pure `with` bracket around the existing body — no return value, exception path, or existing WARNING/INFO log is changed. Verified by the full suite staying green (parity + the ops' own existing tests) and `ruff`/behavior-preserving acceptance criteria. |
| T-45-11 | Denial of service (per-query timing overhead) | hot path | mitigate (by exclusion) | D-09 explicitly EXCLUDES `execute`/`fetch_*` from instrumentation — no per-query `time.perf_counter()` cost is introduced; only coarse heavyweight ops are wrapped. |

No `high`-severity threats. Instrumentation is behavior-preserving and emits only operation metadata.
</threat_model>
